# 启动窗口验证记录

2026-09-22，分支 `feat/startup-progress-webview`，macOS 15.7.2 / arm64。

## 设计来源与构建边界

参考 DeepSeek Harness 工作树 `acd26467c25eea8e8e83b53e5d8ec4e416a274ec` 中的
`ui-theme/src/styles/{base,design-platform}.css` 和 `ui-primitives/src/Button.module.css`。
只复制本窗口实际使用的 token 值和按钮规则，保留来源、版本与 MIT 声明；引用仓库不是服务入口，也不是构建依赖。

- 字体：DSH 的系统字体栈，不下载字体。
- 颜色：白/深灰背景，黑白主按钮，业务蓝、成功绿、错误红。
- 控件：高 36px、圆角 18px、左右内边距 14px、字体 14px/22px。
- 本窗口增加最小宽度 88px；上游通用按钮没有最小宽度。长文案自然撑宽。
- 主题跟随系统，不读取 DSH Web 的 localStorage，也不同步网页内部手动主题选择。
- 保持静态 HTML/CSS/JS；没有 React、Vite、package.json 或 Node/pnpm 构建步骤。

### 测试收尾约束

测试退出曾遗留原生确认框，且 UI 观察会重新启动已经退出的测试 App，导致误用默认开发数据目录。
已先通过停止操作清理该测试实例启动的服务，再结束测试实例；正式配置及退出偏好未改动。
后续一律显式传入临时数据目录，非退出确认专项测试只在该临时目录设置 `confirmQuit=false`。
退出后不再调用会激活应用的 UI 观察接口，使用 PID、服务端口和日志验证清理。
最终本轮测试进程以退出码 0 结束，启动器及其测试服务均无残留；临时浏览器测试页和服务器也已关闭。

最终优化测试包另验收了原生关闭按钮 → 窗口销毁 → 重新打开 → 保留同一 attempt 和等待时间，
以及“转入后台” → 窗口销毁 → 服务随后就绪且 HTTP 200；两个手动入口均有实际 Destroyed 日志。
31 项 Rust 单元测试、`cargo fmt --check`、Clippy `-D warnings`、静态 JS 语法检查和 Release `.app` 构建通过。

已修正实测发现的导航边界：Tauri 在 macOS 把首页规范化为 `tauri://localhost`，路径为空；
白名单须同时接受空路径、`/` 和 `/index.html`。外部页面仍不可导航进入该窗口。

窗口观察工具可能激活应用并触发 macOS Reopen，所以销毁/常驻结论以启动器日志、PID 和 HTTP 探测为准，
不通过反复激活应用来判断“是否自动重开”。原生对话框仍交由 `tauri-plugin-dialog`，未迁入 Webview。

## 对照 cc-switch 轻量模式

核对 [cc-switch 的 lightweight.rs](https://github.com/farion1231/cc-switch/blob/37d0476097754636493ce836faf1a60f2121e340/src-tauri/src/lightweight.rs)
及同版本 `lib.rs` 的退出分类：进入轻量模式调用 `WebviewWindow.destroy()`，按需重新构建窗口；
无存活窗口引发的无退出码事件不应结束托盘进程。没有额外强杀 WebKit GPU 进程的逻辑。

本项目采用相同的销毁/重建方式，且将就绪自动关闭、转入后台、原生关闭按钮统一到显式销毁入口。
进度快照保存在 Rust，重新打开不会重新执行已经完成的初始化；不会保存隐藏窗口句柄。
与 cc-switch 不同，本项目保留用户既有的 Dock 显隐偏好，不为了关闭临时进度窗口强行改写偏好。

## 首轮内存与启动时间（历史采样，本轮未重测）

Release 优化测试包、独立数据目录、禁用自动打开浏览器、固定可控 Runner。
用 `ps` 约每 0.2 秒采样，排除 Runner；通过 `launchctl print pid/<启动器 PID>` 确认所属 WebKit 辅助进程。
下表是 RSS，不是物理内存 footprint；跨进程求和可能重复计算共享页，也不是对所有机器的保证。

| 采样对象 | 结果 |
| --- | --- |
| 启动器主进程峰值 | 86.83 MiB |
| WebKit 辅助进程峰值 | 88.14 MiB |
| 同一时刻合计峰值 | 171.36 MiB |
| 启动约 45 秒时 | 主进程 83.0 MiB + GPU 35.6 MiB，网页内容和网络进程已退出 |
| 已有无 Webview 的旧 Release 产物对照 | 峰值 63.47 MiB，末次 60.34 MiB，无 WebKit 辅助进程；不是同一源码快照的严格 A/B |

这次采样中，从 `open` 调用到窗口创建约 1.42 秒、页面 load 完成约 1.84 秒；这些是日志指标，不是首帧计时。
就绪后 1.21 秒记录到窗口销毁，随后网页内容和网络进程不再存在。
**销毁窗口没有立即归还所有内存**：GPU 进程和部分主进程内存仍驻留，不能宣称恢复到无 Webview 的基线。

## 与 Swift 版的剩余差异

本次只新增启动进度与必要的生命周期保护；运行时管理仍有意排除。
对照历史 Swift 基线 `28c96665` 和当前源码，以下差异仍然存在：

- 没有 Dock 右键服务菜单、多语言、睡眠/唤醒后的探活宽限。
- 登录启动使用 Tauri autostart 的 LaunchAgent，并非 Swift 的 SMAppService；尚未区分登录启动的静默行为。
- About 仍为系统消息框，使用系统提示图标；不展示 bundled runtime receipt。
- 未就绪时的浏览器打开请求不排队；本次提供进度窗口与按需重新打开窗口，不等价于 Swift 的 openWhenReady。
- Unix 外壳遭信号强制终止时仍依赖下次启动清理遗留进程组；主动脱离进程组的后代不在可靠清理边界内。

Windows/Linux 未做本轮 GUI 或内存实测；不能用 macOS 验收代替跨平台验收。
